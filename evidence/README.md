## A five-minute review

1. Read the DMS business problem and contribution, then its architecture and metric definitions.
2. Run the offline sample suite using the [verification guide](verification-guide.md). It needs no tenant credentials.
3. Inspect the engagement-letter person-field example and its documented acceptance gaps.
4. Use the [claim register](claim-register.md) to distinguish reported outcomes from directly runnable public evidence.

## Evidence labels

| Label | Meaning |
| --- | --- |
| Reported experience | Professional account or existing project record; not independently audited here. |
| Reviewed implementation | Existing case study records inspection of configuration or output; raw private material is withheld. |
| Historical aggregate | Public transcription of a bounded execution result; not a new production measurement. |
| Reproducible sample | Public code and synthetic fixtures a reviewer can execute. A passing sample does not validate production. |
| Reference design | Generalized or proposed architecture, procedure, formula, or test plan. |
| Acceptance open | Available evidence does not establish final business acceptance. |

No screenshot, raw production log, certification verification, or demo video is implied by this index. New artifacts follow the [evidence publication template](artifact-template.md).
